# واجهة النسر للتجارة الجديدة

هذه واجهة تأسيسية منفصلة عن التطبيق القديم. لا تغيّر الملفات القديمة ولا تنقل بيانات localStorage تلقائيًا إلى قاعدة البيانات.

## ما تم تأسيسه
- إنشاء حساب وتسجيل الدخول عبر Supabase Auth.
- استعادة جلسة الدخول وتجديدها.
- إنشاء نشاط وربطه تلقائيًا بالمستخدم المنشئ كمالك وفق trigger قاعدة البيانات.
- تحميل عضويات المستخدم النشطة واختيار النشاط عند تعدد الأنشطة.
- قراءة الدور والصلاحيات الإضافية؛ فرض الصلاحيات الحقيقي يبقى في RLS ودوال قاعدة البيانات.

## الإعداد
1. أنشئ مشروع Supabase جديدًا.
2. نفّذ supabase/schema.sql ثم migrations من 002 إلى 009 بالترتيب، ثم supabase/verify_setup.sql.
3. انسخ Project URL و anon/public key من إعدادات المشروع.
4. ضع القيمتين في app/config.js بدل النصوص التجريبية.
5. افتح app/index.html عبر استضافة HTTPS.

لا تضع service_role key في الواجهة مطلقًا. لا تستخدم المشروع تجاريًا قبل تشغيل اختبارات PostgreSQL ومراجعة RLS والدوال على مشروع تجريبي.

## ما لم يكتمل بعد
المنتجات، الأطراف، المشتريات، المبيعات، المرتجعات، التحصيلات، الخزنة، المصروفات، التقارير، التصدير والنسخ الاحتياطي لم تُربط بعد بهذه الواجهة. لن تظهر كوظائف عاملة حتى تنفيذ الربط والاختبار. الواجهة الحالية ليست تطبيقًا أصليًا native؛ هي واجهة ويب responsive قابلة للتثبيت بعد استكمالها.
