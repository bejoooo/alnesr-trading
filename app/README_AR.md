# واجهة النسر للتجارة الجديدة

واجهة ويب عربية RTL منفصلة عن التطبيق القديم. لا تنقل بيانات localStorage تلقائيًا ولا تعتبر الصفحة القديمة قاعدة بيانات مشتركة.

## ما تم تأسيسه
- إنشاء حساب وتسجيل الدخول عبر Supabase Auth مع استعادة الجلسة.
- إنشاء نشاط وربطه تلقائيًا بالمستخدم المنشئ كمالك.
- تحميل عضويات المستخدم النشطة واختيار النشاط عند تعدد الأنشطة.
- قراءة الدور والصلاحيات، مع فرض الصلاحيات فعليًا في RLS ودوال قاعدة البيانات.
- كتالوج المنتجات: إضافة وتعديل الاسم والكود والتصنيف والوحدة والأسعار وحد التنبيه والضمان والمواصفات.
- قراءة أرصدة المخزون من product_stock_balances وسجل حركات المنتج.
- تسويات زيادة/نقص المخزون عبر post_stock_adjustment فقط؛ لا يمكن للتعديل العادي على الكتالوج تغيير الكمية.
- البحث والتصفية حسب حد التنبيه والرصيد المتاح والصفر.

## الإعداد
1. أنشئ مشروع Supabase جديدًا.
2. نفّذ supabase/schema.sql ثم migrations من 002 إلى 009 بالترتيب، ثم supabase/verify_setup.sql.
3. انسخ Project URL و anon/public key من إعدادات المشروع.
4. ضع القيمتين في app/config.js بدل النصوص التجريبية.
5. افتح app/index.html عبر استضافة HTTPS.

لا تضع service_role key في الواجهة مطلقًا. لا تستخدم المشروع تجاريًا قبل تشغيل اختبارات PostgreSQL ومراجعة RLS والدوال على مشروع تجريبي.

## ما لم يكتمل بعد
- صور المنتجات والرفع الآمن إلى Storage.
- فاتورة المشتريات، وإضافة منتج جديد من داخلها، وتسجيل الموردين والدفعات.
- المبيعات والعملاء والمرتجعات.
- الخزنة والمصروفات والتقارير والتصدير والنسخ الاحتياطي.
- الاختبارات الفعلية على قاعدة PostgreSQL وتهيئة مشروع Supabase.
الواجهة الحالية ليست تطبيقًا أصليًا native؛ هي واجهة ويب responsive قابلة للتثبيت بعد استكمالها.
- التقارير والتصدير: تقارير مبيعات ومشتريات ومدفوعات وخزنة ومصروفات ومرتجعات ومخزون وحسابات، مع فلترة حسب تاريخ كل حركة.
- تصدير Excel بصيغة XLSX عبر SheetJS CDN، مع أوراق منفصلة حسب الصلاحيات الممنوحة للمستخدم.
- حدود التقارير موضحة داخل الواجهة: أرصدة المخزون والحسابات حالية، والمستحقات الحالية للفواتير ليست لقطة تاريخية، وهامش البنود تقديري قبل أثر خصم الفاتورة الإجمالي والمرتجعات.
