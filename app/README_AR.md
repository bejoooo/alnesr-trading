# واجهة النسر للتجارة

واجهة عربية RTL متجاوبة لإدارة النشاط، تعمل حاليًا كـ PWA قابلة للتثبيت بعد إعداد الاستضافة. ليست تطبيقًا أصليًا Native حتى الآن، ويمكن بحث تغليفها لاحقًا لتطبيقات Android وiOS.

## ما تم تجهيزه في الواجهة

- تسجيل الدخول وإنشاء الحساب واستعادة الجلسة عبر Supabase Auth.
- إنشاء نشاط وربطه بالمستخدم المنشئ كمالك، وتحميل عضويات المستخدم واختيار النشاط عند تعدد الأنشطة.
- قراءة الدور والصلاحيات وإخفاء الوظائف غير المسموحة في الواجهة؛ ويجب أن تظل الحماية الفعلية مفروضة في RLS ودوال قاعدة البيانات.
- كتالوج المنتجات: الإضافة والتعديل والبحث والتصفية والأسعار والضمان والمواصفات والصور.
- فصل كتالوج المنتجات عن المخزون الفعلي؛ إضافة المنتج وحدها لا تنشئ كمية مخزون.
- تسويات المخزون وسجل الحركات.
- الموردون والمشتريات متعددة البنود، وإضافة منتج جديد داخل فاتورة الشراء، وتوزيع خصم المورد، والدفعات الجزئية وكشف حساب المورد.
- العملاء والمبيعات متعددة البنود، وأسعار الجملة والقطاعي، والخصومات والتحصيلات الجزئية وكشف الحساب وطباعة الفاتورة.
- المرتجعات المرتبطة بالفاتورة الأصلية، مع تحديد الصالح والتالف وتسوية المستحق أو رد النقد.
- الخزنة: الرصيد الافتتاحي والإيداع والسحب والمصروفات وسجل الحركات.
- الأرصدة الافتتاحية للعملاء والموردين.
- تقارير المبيعات والمشتريات والتحصيلات والمدفوعات والمصروفات والخزنة والمرتجعات والمخزون وحسابات الأطراف، مع تصدير XLSX.
- نسخة احتياطية JSON واستعادة آمنة إلى نفس النشاط بشرط أن تكون جداول البيانات المستهدفة فارغة، وبصلاحية المالك فقط.

## إعداد Supabase — على مشروع تجريبي جديد فقط

1. أنشئ مشروع Supabase جديدًا للاختبار، وانتظر حتى يكتمل إنشاؤه.
2. من SQL Editor شغّل الملفات بالترتيب التالي:
   - `supabase/schema.sql`
   - `supabase/002_access_control.sql` حتى `supabase/011_backup_restore.sql` بالترتيب الرقمي دون تخطي أي ملف.
   - بعد اكتمالها شغّل `supabase/verify_setup.sql`.
3. من إعدادات المشروع انسخ Project URL ومفتاح العميل العام publishable/anon.
4. ضع القيمتين فقط في `app/config.js` بدل القيم التجريبية.
5. انشر مجلد `app` على استضافة HTTPS، ثم اختبر إنشاء الحساب والدخول وإنشاء نشاط تجريبي.

**مهم:** لا تضع مفتاح `service_role` أو أي مفتاح سري في ملفات الواجهة أو GitHub. مفتاح العميل العام مخصص للاستخدام من الواجهة، لكن سلامة البيانات تعتمد على RLS وصحة الدوال واختبار الصلاحيات.

## ما لم يتم التحقق منه بعد

- لم يتم ربط الواجهة بمشروع Supabase فعلي؛ ملف `app/config.js` ما زال يحتوي قيمًا تجريبية.
- لم تُشغّل ملفات SQL على خادم PostgreSQL فعلي، ولم ينجح اختبار `verify_setup.sql` على قاعدة حقيقية حتى الآن.
- لم تُختبر معاملات الشراء والبيع والدفعات والمرتجعات والمخزون والخزنة والنسخ الاحتياطي والاستعادة أثناء التشغيل الفعلي.
- لم تُختبر سياسات RLS والصلاحيات بحسابات متعددة وأدوار مختلفة، ولا اختبار عزل نشاط عن نشاط آخر.
- النسخة الاحتياطية JSON لا تتضمن سجل التدقيق ولا الملفات الثنائية لصور المنتجات داخل Storage؛ يلزم الاحتفاظ بنسخة مستقلة من الصور.
- التقارير تعرض بعض الأرصدة الحالية، ولا تمثل بالضرورة لقطة تاريخية للأرصدة كما كانت في نهاية فترة سابقة. كما أن بعض هوامش الربح المعروضة تقديرية قبل التسويات النهائية والمرتجعات.

لا تستخدم النظام في التشغيل التجاري أو تُدخل بيانات حقيقية قبل اجتياز اختبارات قاعدة البيانات والصلاحيات والعمليات المحاسبية على بيئة تجريبية.
